# Mando en la Odin 3 — arquitectura definitiva (18/10/2026)

Resumen de cómo queda resuelto tener **botón QAM** y **mando en emuladores
(RetroArch y standalone)** a la vez, y por qué.

## Cadena de mando

```
AYN Odin3 Gamepad (event6, físico)
   │  InputPlumber lo captura (EVIOCGRAB) y aplica el capability map:
   │  BTN_BACK -> QuickAccess  (botón QAM)
   ▼
InputPlumber 0.82 — target_devices: [deck-uhid, keyboard]
   │  deck-uhid = HID virtual real (/dev/hidraw0, 28DE:12F0
   │  "Generic Steam Controller"), NO un pad uinput
   ▼
Steam Input (ACTIVADO en el acceso directo de DeckStation)
   │  Steam lee ese pad Deck por hidraw y emite su pad virtual XInput
   ▼
Juegos y emuladores (SDL/udev)  ->  ven el pad virtual  ✓
RetroArch                       ->  J1 = pad virtual      ✓
```

## Por qué así (evidencias)

- **Batocera**: no usa InputPlumber. Mando físico libre + reglas udev/evmapy.
  Todo funciona, pero no hay pad virtual ni QAM unificado.
- **Armada**: InputPlumber con target **`deck-uhid`** + `inputplumber-intercept`
  (modos overlay/gamepad, para la UI, **no** para liberar el mando).
- **Medido aquí**:
  - `InterceptMode` 0–4 y `passthrough: false|true` **no liberan** el físico
    (InputPlumber captura siempre: 1 fd sobre `event6` en todos los casos).
  - Con target `deck` el pad virtual es **uinput** y **SDL no lo ve**
    (pygame: 0 pads virtuales, solo el AYN).
  - Con target `deck-uhid` InputPlumber crea `/dev/hidraw0` `28DE:12F0`
    (el kernel **no** le crea nodo evdev; SDL por udev tampoco lo ve).
  - **Pero** Steam sí lo lee, y con **Steam Input activo** Steam emite un pad
    virtual que SDL sí ve → RetroArch y standalone funcionan (probado con Cemu
    por Fransis el 18/10).

## Configuración que hay que mantener

1. `inputplumber` con `target_devices: [deck-uhid, keyboard]`
   (`/usr/share/inputplumber/devices/01-ayn-controller.yaml`, en el BSP).
2. Regla udev `70-pocknix-inputplumber-uhid.rules`:
   `hidraw 0003:28DE:12F0.* -> GROUP=input MODE=0660`.
3. **Steam Input activado** para el acceso directo de **DeckStation/ES-DE**
   (Propiedades → Mando → "Habilitar Steam Input").
   Sin esto, los standalone no reciben mando.
4. RetroArch: `input_player1_joypad_index = "1"` (pad virtual).

## Hotkeys de RetroArch (con Steam Input)

Steam Input **no reenvía Guide** al juego (lo consume Steam), así que la
combinación antigua Guide+X no llega. Valores actuales:

| Acción | Botón | Índice |
|---|---|---|
| Habilitar hotkey | **Select/Back** | 6 |
| Menú | **X** | 2 |
| Salir | Start | 7 |
| Guardar estado | LB | 4 |
| Cargar estado | RB | 5 |

→ **Select + X = menú de RetroArch**.

## Re-escaneo de InputPlumber

La regla udev `60-input-id2-odin3-gamepad-rescan.rules` reiniciaba InputPlumber
cuando el mando interno aparece tarde. Al ocultar/mostrar el dispositivo,
InputPlumber volvía a dispararla → **bucle de reinicios** → `start-limit-hit`
→ consola sin mando (visto con 0.75.2 y 0.82). Arreglado con un sello
`/run/pocknix/inputplumber-rescan.done`: **un solo reinicio por arranque**.
