# ReTri ARM en la Odin 3 — instalación y estado (28/11/2026)

ReTri es la **recompilación estática de Echoes of Wisdom** de `peiikai/ReTri`. En Linux solo
hay build oficial **x86-64** (releases `v0.1.x`); **aarch64 está solo en los nightly** y el
propio proyecto lo marca como *“not well tested yet”*. Aquí se probó esa build ARM nativa
(sin Box64) en la Odin 3.

## Instalación

- Build: `ReTri-nightly-202611281754-9dd2c34-linux-arm64.tar.gz` (nightly del 28/11).
- Destino: **`/home/games/linux/ReTri/`** (SD; bind de `/opt/decomps`), con `run.sh` para que
  `calvos-decomps-sync` cree el atajo de Steam y `calvos-run` lo lance.
- Archivos del juego: carpeta con `exefs/` + `romfs/` (base **1.0.0**, sacada del `.xci`).
  El setup se hizo **sin ventana**:

```sh
cd /home/games/linux/ReTri
./AppRun --prepare --game-files /home/games/linux/eow-files
```

- **Ojo con el entorno**: `--prepare` sigue inicializando una ventana SDL; desde SSH hay que
  pasar la sesión real (`XDG_RUNTIME_DIR=/run/user/1001`, `WAYLAND_DISPLAY=wayland-1`).
  Con `DISPLAY`/`XDG_RUNTIME_DIR` incorrectos o `SDL_VIDEODRIVER=dummy` aborta en
  `ui_window_init()` (`FATAL: SDL_CreateWindow: Vulkan support ... dummy`).
- El setup tardó ~19 min: **la compilación del código del juego son 1081 s** (`zig cc`, 1604
  objetos) + shaders. Queda en el propio directorio (`portable.txt`): **8,8 GB**.
- **`userfaultfd`**: el kernel 7.2.15 de CalvOS **no lo tiene** (`# CONFIG_USERFAULTFD is not
  set`) y el juego avisa `[plat] no page write tracking`. **No es fatal**: el proyecto lo
  soporta (pierde el *write tracking* del vertex cache/texturas). Enabling it would be a
  kernel config change (`CONFIG_USERFAULTFD=y` + `vm.unprivileged_userfaultfd=1`), útil también
  para otros recomp/emuladores.

## Qué se vio al jugar

- Corre nativo en **Turnip** (`Adreno 830`, `Mesa 26.3.0-pocknix2.2`, Vulkan 1.4.363).
- Picos de **55-59 fps** y caídas a 25-47 fps; `max` de frame de 464-945 ms al compilar
  pipelines.
- **Fallos gráficos**: en el log aparece
  `[tex] type mismatch: want 3 have 1 (1408x792x1 target 1 fmt 0x35 layers 1)` — una vista de
  textura con tipo distinto al esperado. Es el candidato a los artefactos.
- **Congelación**: el render se para y **el audio sigue**; **no hay ningún error en `dmesg`**
  (ni `msm` ni fallo de GPU), y el log termina con fps normales (el proceso se cierra al
  cerrar la ventana). Apunta a un cuelgue del hilo de render (espera de fence/Vulkan) o a un
  bug del port ARM, no a un *hang* del driver a nivel de kernel.
- Logs: `/home/games/linux/logs/ReTri-*.log` (los de `calvos-run`) y el del propio juego en
  `/home/games/linux/ReTri/eowrecomp.log` (con backups `eowrecomp-backup-*.log`).

## ¿Es culpa nuestra?

No hay nada nuestro en la cadena salvo el empaquetado. **Mesa/Turnip es el paquete de pocknix**
(`2:26.3.0-2`, build recortado para RP6; no lleva parches nuestros) y el kernel solo aporta la
falta de `userfaultfd` (aviso, no error). Los síntomas encajan con la familia de issues abiertos
del proyecto:

| Issue | Qué cuenta |
|---|---|
| [#137](https://github.com/peiikai/ReTri/issues/137) | Crash al salir de una casa/cueva: **SIGSEGV dentro del driver Vulkan** (`libvulkan_radeon.so`) |
| [#138](https://github.com/peiikai/ReTri/issues/138) | Crash en la secuencia de la prisión (*NVN command memory overflow*) |
| [#136](https://github.com/peiikai/ReTri/issues/136) | Sombras/shaders mal en el nightly de Android |
| [#134](https://github.com/peiikai/ReTri/issues/134) | Cámara que salta en vez de interpolar |

La build **ARM es nightly y no está bien probada**; el glitch de textura y el cuelgue son
reportables con el log y las specs (abajo). Antes de reportar conviene, si se puede, **reproducir
el cuelgue y sacar un backtrace** con `gdb -p <pid>` (`thread apply all bt`): si el hilo de
render está dentro de `libvulkan_freedreno.so`, el foco es Turnip; si está en el binario, es el
port.
